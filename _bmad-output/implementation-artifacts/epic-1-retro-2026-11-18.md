## Funn

### Hva gjennomgangene fanget

Det var 52 reviewfunn til sammen. 18 ble rettet, 2 utsatt, og resten avvist med begrunnelse. Tre mønstre går igjen, og alle tre ville gått videre uten review.

**A. Innstillinger ingen ba om**
- Story 1.2, funn 1: `cacheComponents` og `partialPrefetching` var lagt i `next.config.ts`. Malen i create-next-app 16.4.6 har tom konfig, så linjene var lagt til av KI-en selv. Cache Components endrer renderingsmodellen som Epic 6 arver. Begge er fjernet ([spec-1-2](spec-1-2-frontend-skjelett-med-proxy-til-backend.md), triage nr. 1). I dag står bare `agentRules`, `rewrites`, `proxyTimeout` og `agentUpgrade` i [next.config.ts](../../frontend/next.config.ts).
- Det motsatte tilfellet ble også fanget ved egen kontroll: `next dev` skrev `AGENTS.md` på nytt når den oppdaget en KI-agent. Det er slått av med `agentRules: false` (sesjonslogg 988). Her var det verktøyet som endret repoet uten at noen ba om det.
- Story 1.2, funn 5: `npm install x` legger til `^` som standard. Det er nå en test for at alle pakker er låst med `~` ([oppsett.test.ts:30](../../frontend/tests/oppsett.test.ts)).
- **Disposisjon:** rettet. Lærdommen blir regel R1.

**B. Tester som ikke kunne feile, eller som var smalere enn kravet**
- Story 1.2, funn 2: akseptkriteriet «`backend/data/prognos.db` er ikke rørt» ble sjekket med `git status`. Den sjekken kan aldri slå ut, fordi `*.db` er gitignored (`.gitignore:68`). Den er erstattet av [e2e/database.spec.ts](../../frontend/e2e/database.spec.ts).
- Story 1.1, funn 5 og 8: versjonsvakten var ikke testet med tom tabell eller to rader, og ingen test festet `STANDARD_DB_STI`. Funn 9: 405-testen sjekket ikke `Allow`.
- Story 1.2, funn 4: skanningen etter forbudte strenger filtrerte på filendelse, så `.json`, `.svg` og `.md` slapp gjennom.
- Story 1.3, funn 2: `.db`-testen dekket ikke `-journal`, `-wal`, `-shm` og `.sqlite`.
- **Disposisjon:** alt er rettet. Lærdommen blir regel R2.

**C. Feil som bare kommer fram i Windows-miljøet**
- Story 1.2, funn 7: `npm test` feiler når stasjonsbokstaven er liten (`c:\…`). Feilen ligger i Vitest/Vite. Den ble reprodusert, rundgangene for cmd og Git Bash ble testet, og README anbefaler PowerShell (`f07911e`, `deferred-work.md`).
- **Disposisjon:** godtatt slik det er, med README-merknad. Brukeren valgte bort `scripts/test.mjs`. Lærdommen blir regel R3.

### Overgangen mellom storyene

- **Speccen for 1.2 anbefaler fortsatt sjekken som ikke kan feile.** Verification-delen i [spec-1-2](spec-1-2-frontend-skjelett-med-proxy-til-backend.md) har fortsatt `git status --short backend/data -- expected: ingen endring etter Playwright`. Det er nettopp sjekken funn 2 viste aldri kan feile. Den som gjenbruker speccen som mal i Epic 6, arver feilen. **Disposisjon:** rett nå (spec-avstemming, tiltak 2).
- Backend og proxy henger sammen: 404-testen i 1.2 sammenligner proxy-svaret byte for byte, også `content-type`, med backendens norske `{detail}` fra 1.1. Overgangen er dekket.
- AD-9 er bare delvis dekket: norske svar for 422 og uhåndterte unntak mangler (Story 1.1, funn 2). Det er bevisst utsatt til Epic 3 og ført i `issues.md`. **Disposisjon:** utsatt.
